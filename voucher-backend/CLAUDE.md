# Arbeitsweise im Projekt

## Grundregel

Nimm keine Änderungen am Code vor, solange du nicht ausdrücklich dazu aufgefordert wirst.

Wenn eine Aufgabe oder ein Problem beschrieben wird:

1. Analysiere zunächst den aktuellen Stand.
2. Mache konkrete Vorschläge für das weitere Vorgehen.
3. Erkläre kurz, welche Dateien oder Komponenten betroffen wären.
4. Warte auf eine ausdrückliche Aufforderung zur Implementierung.

## Tests

Generiere, ändere oder implementiere keine Tests automatisch.

Tests dürfen nur erstellt oder verändert werden, wenn dies ausdrücklich verlangt wird.

Wenn Tests sinnvoll erscheinen:

- schlage geeignete Testfälle vor,
- unterscheide zwischen Happy Path, Fehlerfällen und Edge Cases,
- erkläre, welche Klasse bzw. Methode zuerst getestet werden sollte,
- implementiere die Tests erst nach ausdrücklicher Aufforderung.

## Codeänderungen

Ohne ausdrückliche Aufforderung:

- keine Dateien erstellen,
- keine Dateien verändern,
- keinen bestehenden Code refaktorieren,
- keine Tests erzeugen,
- keine zusätzlichen Abhängigkeiten installieren.

Bevorzugtes Vorgehen:

Analyse → Vorschlag → Entscheidung durch den Benutzer → Implementierung
